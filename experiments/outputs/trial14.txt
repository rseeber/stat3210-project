Gopher is an older way to browse and retrieve files over the internet. Think of it as navigating a directory tree: a Gopher server gives your client a menu of items, and choosing one asks the server for that item. Menus identify each item with a type code, a selector (roughly, its path), and the host and port where it lives. In the basic protocol, the client connects over TCP—usually on port 70—and sends the selector as a line of text. The server returns a menu or a file. <citation src="8"></citation><citation src="6"></citation>

The **Web** is a broader system built around HTTP and formats such as HTML. HTTP responses include status and content-type information; HTML pages can have links embedded in text, and the modern Web adds styling and scripting. Gopher is more menu-oriented and has far fewer built-in conventions: its menus are lists of links, and the item type helps the client infer what it is retrieving. So Gopher and HTTP both let clients request remote resources, but browsing them feels quite different. <citation src="8"></citation><citation src="9"></citation>

**Gemini borrows Gopher’s minimalist, text-first spirit, but it isn’t simply Gopher with a new name.** Gemini uses a small document format called Gemtext, where links are written on their own lines rather than embedded in text. Its request sends a full URL, and its response begins with a status code and content-type—features absent from basic Gopher. Gemini also requires TLS, while basic Gopher does not. A useful shorthand: **Gopher is like a network of simple menus; Gemini is a deliberately small, encrypted hypertext system inspired by Gopher and shaped by lessons from the Web.** <citation src="11"></citation><citation src="13"></citation><citation src="5"></citation>
