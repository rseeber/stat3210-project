You may mean Gopher. It’s an older internet protocol, developed at the University of Minnesota around 1991, for finding and retrieving documents. The basic experience is menu-driven: a server sends a plain-text menu, and each menu item tells the client what kind of resource it points to and where to request it. Selecting an item makes another request. Gopher can carry files as well as text, but its menus and documents are much less flexible than modern web pages. citeturn0search0

Compared with the web and HTTP: HTTP is the protocol that transfers web resources; HTML is the common format for web pages. HTTP grew to support many kinds of requests, metadata and content, while browsers render rich pages with styling, scripts, images and interactive features. Gopher is more narrowly oriented around retrieving items from menus, with little built-in support for page layout or interaction. So Gopher is not simply an early version of HTTP—the two are different ways to organize and retrieve information.

Gemini’s connection: Gemini, created much later, was explicitly inspired by Gopher’s minimalist approach, but it is a separate protocol—not a Gopher upgrade. It keeps the focus on lightweight documents and simple navigation, while using encrypted TLS connections and its own link-friendly text format, Gemtext. Gopher menus use compact, position-dependent item records; Gemini pages use readable text lines, with a special form for links.
